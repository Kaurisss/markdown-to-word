# 设置界面配置项分析

分析日期：2026-07-13

## 结论

当前设置界面已经覆盖基础应用偏好，但仍缺少数据恢复、导出行为、样式预设和配置管理等高频能力。

后续迭代不宜继续堆叠零散开关，应先明确以下三类配置的边界：

1. 应用偏好：主题、编辑器显示、自动保存和快捷键等。
2. 新文档默认值：新建文档时使用的默认排版和页面配置。
3. 当前文档配置：仅影响当前正在编辑和导出的文档。

建议优先增加自动保存恢复、配置备份、导出默认行为和样式预设。

## 当前配置能力

### 偏好设置

- 浅色和深色主题。
- 编辑器、双栏和导出预览三种默认视图。

### 编辑器设置

- 自动保存。
- 编辑器与预览同步滚动。
- 底部状态栏。
- 编辑器字号。
- 编辑器行高。
- 自动换行。

### 默认样式

- 默认中文字体。
- 默认英文字体。
- 默认字号。
- 默认行距。
- 默认段后间距。
- 默认对齐方式。

### 快捷键

- 自定义快捷键。
- 快捷键冲突检测。
- 单项重置和全部恢复默认。

### 当前文档页面配置

以下选项已经存在，但位于顶部“布局”功能区，而不是应用设置页面：

- 页边距和纸张尺寸。
- 页眉、页脚和页码。
- 目录层级和正文起始页码。
- 分割线处理。
- 表头加粗。
- 中文标点规范化。
- 正文、标题、代码、引用、表格和题注样式。

## 建议增加的配置项

### P0：优先实现

#### 自动保存间隔

当前自动保存延迟固定为 1 秒。建议提供：

- 1 秒。
- 5 秒。
- 15 秒。
- 30 秒。
- 关闭。

#### 草稿恢复策略

建议提供：

- 启动时自动恢复上次草稿。
- 启动时询问是否恢复。
- 不恢复草稿。

同时增加“清除自动保存草稿”操作，并显示草稿最后保存时间。

#### 未保存内容保护

在以下操作前检测内容变化并进行确认：

- 新建文档。
- 导入其他文件。
- 关闭应用。
- 清除草稿。

#### 设置备份与恢复

增加独立的“数据与恢复”页面，支持：

- 导出应用设置。
- 导入应用设置。
- 导出文档样式配置。
- 导入文档样式配置。
- 恢复应用默认设置。
- 恢复默认文档样式。
- 清除全部本地数据。

导出配置时不应默认包含 AI API Key 等敏感信息。

### P1：高价值改进

#### 默认导出目录

支持记住上一次导出目录，也可以让用户指定固定目录。建议保留“每次询问保存位置”选项。

#### 文件名模板

支持通过占位符生成导出文件名，例如：

```text
{title}_{date}.docx
```

可考虑的占位符：

- `{title}`：第一个一级标题或文档标题。
- `{date}`：当前日期。
- `{time}`：当前时间。
- `{source}`：导入文件名称。

#### 导出完成后的动作

提供以下选项：

- 仅显示成功提示。
- 自动打开导出的 Word 文件。
- 打开文件所在目录。

#### 样式预设

允许将完整文档配置保存为命名预设，例如：

- 公文格式。
- 论文格式。
- 工作报告。
- 读书笔记。
- 简洁文档。

预设应支持：

- 新建。
- 重命名。
- 复制。
- 删除。
- 导入和导出。
- 设为新文档默认预设。
- 将当前文档配置保存为预设。

#### 跟随系统主题

主题模式建议扩展为：

- 跟随 Windows。
- 浅色模式。
- 深色模式。

### P2：按需实现

#### 编辑器行为

- Tab 缩进宽度。
- Tab 键插入空格或制表符。
- 当前行高亮。
- 行号显示。
- 拼写检查。
- 编辑器字体。
- 粘贴文本时是否保留 Markdown 格式。

这些能力需要先确认当前 Markdown 编辑器组件是否稳定支持。

#### 预览行为

- 实时生成导出预览。
- 手动刷新预览。
- 预览刷新延迟。
- 默认预览缩放。
- 记住预览滚动位置。

其中“仅在预览面板可见时生成预览”更适合作为内部自动优化，不应要求用户手动配置。

#### 搜索与替换

- 记住大小写匹配设置。
- 记住全词匹配设置。
- 记住正则表达式设置。

#### 窗口行为

- 记住窗口大小和位置。
- 启动时恢复上次窗口状态。
- 默认最大化启动。
- 窗口栏显示模式。

窗口栏显示模式此前已有相关实现和变更记录。如果重新引入，应先确认不同模式确实有持续使用价值。

## 功能优化补充

补充日期：2026-07-14

以下两项不属于普通设置选项，而是会改变文档、文件路径和导出流程的基础能力。实施时应作为独立功能建设，设置页面只承载其中确实需要用户配置的部分。

### 普通文件夹工作区与多文档管理

将当前“单个内存 Markdown 字符串”升级为“普通文件夹工作区 + 单个活动文档”模型。

核心目标：

- 用户可以选择任意普通文件夹作为工作区，不要求使用应用专属目录结构。
- 一个工作区可以包含多个 Markdown 文档，但编辑区同时只打开一个活动文档。
- WindowBar 左侧增加工作区入口，通过左侧 Sheet 浏览和切换文件。
- 文件树按需加载目录，避免打开大型工作区时递归扫描全部文件。
- 记住最近 5 个工作区，并在启动时尝试恢复上次工作区和最后打开的文档。
- 每个 Markdown 文档保存独立的 `DocumentConfig`，新建文档继承工作区默认样式。

文件树第一阶段支持：

- 显示文件夹、Markdown、文本文件和支持的图片文件。
- 隐藏 `.md2word/` 元数据目录和不支持的文件类型。
- 搜索、新建 Markdown、新建文件夹、重命名、刷新、复制相对路径和在资源管理器中显示。
- 删除文件时进入 Windows 回收站，不直接永久删除。
- 当前文档节点显示活动状态和未保存状态。

文档切换必须保护未保存内容：

- 自动保存开启时，先保存当前文档再切换。
- 自动保存关闭时，提供“保存 / 不保存 / 取消”。
- 保存失败时保持当前文档，不执行切换。
- 当前文档被外部删除或重命名时，不静默丢弃编辑内容。

工作区元数据建议保存在：

```text
.md2word/workspace.json
```

其中保存工作区默认样式和以 Markdown 相对路径为键的文档配置。文件树展开状态、Sheet 滚动位置等个人 UI 状态应保存在本地，不写入工作区文件，避免影响 Git 协作。

### Markdown 图片资源预览与 Word 导出

建立从 Markdown 图片引用、工作区资源解析、编辑器预览到 Word 导出的完整图片链路。

路径规则：

- 相对图片路径以当前 Markdown 文件所在目录为基准解析。
- 不修改已有 Markdown 中合法的相对路径。
- 工作区外部路径和绝对路径默认不直接读取。
- 外部图片需要通过显式操作复制到工作区，并更新 Markdown 引用。
- 支持 PNG、JPG、JPEG、GIF 和 WebP，第一阶段不支持 SVG。

新图片导入规则：

1. 当前 Markdown 同级存在 `images/` 时保存到该目录。
2. 不存在 `images/` 但存在 `assets/` 时保存到 `assets/`。
3. 两者都不存在时创建 `images/`。

插入的 Markdown 引用应始终相对于当前文档生成，并使用图片文件名去除扩展名作为默认 `alt`。图片选择、拖拽和剪贴板粘贴应复用同一套导入逻辑。

工作区图片浏览：

- 单击图片节点，在工作区 Sheet 底部显示缩略图、文件名、尺寸、大小和相对路径。
- 缩略图通过 Tauri 读取二进制并创建 Blob URL。
- 切换图片、关闭 Sheet 或组件卸载时必须释放 Blob URL。
- 双击缩略图后使用最大化画廊浏览当前目录中的同级图片。
- 画廊按文件名自然排序，并支持上一张、下一张、缩放、适应窗口和旋转。

预览和导出必须复用相同的资源解析规则：

- Python 后端识别 Markdown 图片并嵌入 DOCX。
- 图片超过页面可用宽度时保持比例缩小，小图片不强制放大。
- 缺失图片、损坏图片、越出工作区和不支持格式应返回包含原始引用与解析路径的明确错误。
- 当前文档配置可增加 `useAltText` 和 `autoNumber`，控制是否使用图片 `alt` 生成题注以及是否自动显示“图1、图2”等编号。
- 预览与 Word 导出的图片题注行为必须一致。

这项能力依赖工作区提供稳定的 Markdown 文件路径和资源根目录，因此实施顺序应先完成工作区路径模型，再接入图片导入、预览和导出。

## 关键设计问题

### 默认样式会直接影响当前文档

当前实现会在应用设置变化时，将默认字体、字号、行距、段后间距和对齐方式写入当前文档配置。

因此，“默认样式”目前并非只影响新文档，而更接近全局强制样式。后续实现样式预设或多文档能力前，应将其拆分为：

- 新文档默认样式。
- 当前文档样式。
- 可复用的样式预设。

相关代码：

- `src/App.tsx`
- `src/components/settings/DefaultStylesSection.tsx`
- `src/config/documentConfigStorage.ts`

### 自动保存只有一个草稿槽位

当前自动保存内容使用单个 LocalStorage 键，没有保存时间、原始文件路径、内容版本或文档标识。

可能产生的问题：

- 开启自动保存后恢复到较早的草稿。
- 导入新文件后覆盖原草稿。
- 用户无法判断草稿是否仍有价值。
- 无法恢复到多个历史版本。

第一阶段至少应增加保存时间、恢复确认和清除入口。只有在支持多文档后，才需要进一步实现多草稿管理。

相关代码：

- `src/features/settings/store.ts`
- `src/features/editor/useAutoSave.ts`
- `src/features/editor/useEditorState.ts`

### 导出行为完全固定

当前导出流程每次显示保存对话框，并根据第一个一级标题或当前日期生成建议文件名。

建议将目录、文件名模板和导出完成后的动作抽成导出设置，同时保留当前行为作为默认值。

相关代码：

- `src/features/export/useExport.ts`

### 导出级预览持续生成

当前导出级预览使用固定 1 秒延迟生成。预览组件即使在纯编辑器视图中仍保持挂载，可能继续触发后端预览生成。

建议优先自动做到：

- 只有预览区域可见时才生成。
- 内容和样式未变化时不重复生成。
- 新请求开始时取消或忽略旧请求。

在此基础上，再决定是否需要向用户开放刷新策略。

相关代码：

- `src/features/preview/useExportPreview.ts`
- `src/components/preview/Preview.tsx`
- `src/App.tsx`

### 偏好设置描述与实际选项不一致

当前偏好设置描述包含“语言、窗口”，实际界面只有主题和默认视图。

短期应修改描述；只有在完成国际化基础设施后，才适合加入语言选择。

相关代码：

- `src/components/settings/SettingsPage.tsx`
- `src/components/settings/AppearanceSection.tsx`

## 建议实施顺序

### 基础能力阶段

1. 建立普通文件夹工作区、路径模型和文件系统适配层。
2. 实现工作区 Sheet、按需加载文件树和文档切换保护。
3. 将 `DocumentConfig` 和自动保存迁移为按工作区、按文档存储。
4. 打通 Markdown 图片的相对路径解析、预览和 Word 导出。
5. 增加图片导入、缩略图详情和同目录画廊。

### 第一阶段

1. 修正“默认样式”的作用范围和命名。
2. 增加自动保存间隔、恢复策略和清除草稿。
3. 增加设置导入、导出和恢复默认。
4. 增加跟随系统主题。

### 第二阶段

1. 增加默认导出目录和文件名模板。
2. 增加导出完成后的动作。
3. 增加样式预设管理。
4. 优化隐藏预览时的后端生成行为。

### 第三阶段

1. 增加编辑器缩进和辅助显示。
2. 增加窗口状态恢复。
3. 根据真实需求决定是否建设国际化和多文档草稿管理。

## 暂不建议增加

- 在没有国际化基础设施时增加语言下拉框。
- 将页面边距、页眉、页脚等当前文档参数重复放入应用设置。
- 将性能优化全部暴露为用户开关。
- 在没有多文档模型时增加复杂的最近文件和多草稿设置。
- 将 AI 平台、模型和 API Key 配置混入通用设置页面。

这些能力要么已经有更合适的入口，要么应由应用自动处理。
