# 将 AI 配置与设置整合进主窗口

## Goal

将 AI 配置和应用设置从两个独立 Tauri Webview 窗口改为主窗口内的页面切换，减少多窗口管理与跨窗口状态同步，让用户可以在编辑器、AI 配置和设置之间直接导航。

## Background

- 当前 `src/App.tsx` 通过 `?window=config` 和 `?window=settings` 将同一 React 应用分流为主编辑器、AI 配置窗口和设置窗口。
- 当前 `src/components/header/Header.tsx` 使用 `WebviewWindow` 动态创建标签为 `ai-config` 和 `settings` 的独立窗口。
- `AIConfigWindow` 和 `SettingsWindow` 都包含面向独立无边框窗口的标题栏、关闭行为和首次渲染后显示窗口的逻辑。
- 设置与 AI Store 当前包含 `BroadcastChannel` / `storage` 事件形式的跨窗口同步逻辑；整合后应评估并移除只为多窗口存在的复杂度。
- 主窗口自身已经具有自定义窗口栏与窗口控制按钮，窗口最小尺寸为 `800x500`。

## Requirements

- 在主窗口中提供编辑器、AI 配置和应用设置三个可切换的顶层页面。
- 切换到 AI 配置或设置时，隐藏编辑器 Ribbon 和编辑区，显示对应的专用全页界面。
- AI 配置页和设置页使用统一的紧凑顶部栏，包含返回编辑器、当前页面标题、可拖动区域以及主窗口最小化、最大化和关闭按钮。
- 原“打开 AI 配置”和“打开设置”入口改为切换主窗口页面，不再创建新的 Tauri Webview 窗口。
- AI 平台、API、模型管理能力保持可用。
- 外观、编辑器、默认样式、快捷键和关于设置能力保持可用。
- 从配置页或设置页返回编辑器后，当前 Markdown 内容和文档配置不得丢失。
- 主编辑工作区在页面切换期间必须保留会话状态，包括光标位置、编辑器与预览滚动位置、当前 Ribbon 标签和其他已打开的临时编辑状态。
- AI 配置页再次打开时保留最后选中的 AI 平台；设置页再次打开时保留最后选中的设置分区。
- 离开 AI 配置页时关闭页面内弹窗、API 指南和敏感信息显示，并清理未提交的平台或模型表单；已保存的数据不得回滚。
- 页面切换期间主题与持久化设置继续立即生效。
- 配置页和设置页不再执行独立窗口专用的显示、关闭、主题同步或拖拽标题栏逻辑。
- 清理不再需要的辅助窗口权限、URL 参数路由和跨窗口同步代码，但不得影响主窗口控制、导入、导出或文件拖放。

## Acceptance Criteria

- [x] 点击“AI 配置”入口后，主窗口内容切换为 AI 配置页，且不会创建 `ai-config` Webview 窗口。
- [x] 点击“设置”入口后，主窗口内容切换为设置页，且不会创建 `settings` Webview 窗口。
- [x] AI 配置页和设置页都提供明确的返回编辑器操作。
- [x] 配置页顶部不显示编辑器 Ribbon，但保留主窗口拖动及最小化、最大化、关闭能力。
- [x] 返回编辑器后，切换前的 Markdown 内容、编辑器/预览视图模式和文档样式配置仍然存在。
- [x] 返回编辑器后，光标、编辑器与预览滚动位置、当前 Ribbon 标签保持在切换前的位置。
- [x] 再次进入 AI 配置或设置时恢复上次选中的平台或分区，但不会重新打开离开前的弹窗或恢复未提交表单。
- [x] AI 配置的新增、编辑、启用、模型管理和 API 指南功能仍可使用。
- [x] 设置各分区仍可切换，修改主题和编辑器设置后主窗口立即反映结果。
- [x] 应用不再根据 `?window=config` 或 `?window=settings` 渲染辅助窗口页面。
- [x] 前端不再调用 `WebviewWindow` 创建 AI 配置或设置窗口。
- [x] Tauri capability 不再声明 `ai-config`、`settings` 窗口或只为创建辅助 Webview 所需的权限。
- [x] 相关组件测试、TypeScript 检查和任务范围 lint 通过；共享导航行为有回归测试覆盖。

## Out Of Scope

- 改变 AI Provider、模型或应用设置的数据结构。
- 重设计 AI 配置表单、设置分区内容或编辑器主体功能。
- 引入通用路由库或新的全局状态库。
