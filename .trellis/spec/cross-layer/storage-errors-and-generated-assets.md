# Storage Errors And Generated Assets

## Local Storage

The app stores three main kinds of front-end state:

- Document style config under `md2word_document_config` in `src/config/documentConfigStorage.ts`.
- App settings under `md2word_settings` plus legacy `app_theme` in `src/features/settings/store.ts`.
- AI built-in/custom provider config and selected model in `src/features/ai/store.ts`.

Storage code should tolerate malformed or older data:

- `documentConfigStorage.ts` catches JSON/storage errors and falls back to `DEFAULT_CONFIG`.
- `normalizeDocumentConfig` delegates to the Zod-backed `parseDocumentConfig`, which fills nested defaults and preserves numeric `pageMargin` compatibility.
- `settings/store.ts` fills missing settings and keyboard shortcuts.
- AI store falls back to built-in providers when parsing fails.

Persisted booleans must not use `z.coerce.boolean()`: `"false"` is truthy in JavaScript and would become `true`. Live/AI schemas reject string booleans; storage migration may explicitly map only `"true"` and `"false"`.

When adding persisted fields, include migration/default behavior and tests.

## Multi-Window Sync

Settings and AI config windows are separate Tauri webviews. Both stores use `BroadcastChannel` as the primary notification mechanism and browser `storage` events as a fallback; each notification calls the store's `persist.rehydrate()`.

Do not assume React state in one window automatically updates another window. Persist before posting the channel notification, retain the storage-event adapter, and test both handler paths.

## Error Mapping

Backend errors travel across layers:

1. Python raises a typed exception from `backend/errors.py`.
2. `backend/backend.py` prints `Error: ...` and exits with a numeric code.
3. Tauri shell plugin returns code/stderr to `pythonBackend.ts`.
4. `parseBackendError` maps code/stderr to Chinese user-facing messages.

If adding an error class or changing exit codes, update backend tests and front-end error parsing tests.

Special case: on Windows, locale-encoded stderr may cause an invalid UTF-8 error before stderr is inspectable. `pythonBackend.ts` catches this and shows a neutral export failure message that mentions common file-lock causes.

## Generated Assets

Generated or packaged assets include:

- `src/index.css` token blocks generated from `src/design/tokens.json`.
- `src-tauri/binaries/md2word-*.exe` generated by `pnpm run build:backend`.
- Tauri icon assets under `src-tauri/icons/`.

Rules:

- Edit `tokens.json`, then run `pnpm run generate:tokens`; do not hand-edit generated token values as the source of truth.
- If backend code changes for a release/package task, rebuild the sidecar with `pnpm run build:backend` and commit the updated binary when the task requires packaging.
- Do not commit build output from `dist/`, `build/`, or `src-tauri/target/`.
